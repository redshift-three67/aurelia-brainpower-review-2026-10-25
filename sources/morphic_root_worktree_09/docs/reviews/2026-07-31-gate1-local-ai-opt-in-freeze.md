## Accepted Behavior

- Web and direct CLI scans default local AI to off.
- The Web request uses one strict boolean and maps opt-in to one CLI flag.
- The interpretation subprocess receives `--llm` only after explicit opt-in.
- Disabled mode constructs no Ollama client and performs no Ollama request.
- Opted-in Ollama is restricted to HTTP loopback and the pinned model; proxies,
  redirects, credentials, paths, queries, fragments, invalid ports, and model
  substitution fail closed or fall back safely.
- Reports distinguish disabled, actual Ollama output, and rule-based fallback.
- Only actual model output is labelled as generated by local AI.
- The opt-in is excluded from templates, client drafts, and browser storage.
  The server store strips only the exact top-level `local_ai_enabled` key and
  does not mutate caller payloads.
- Scores, profile selection, sources, Registry behavior, and scan findings are
  unchanged.
