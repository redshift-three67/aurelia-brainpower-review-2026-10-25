## 1. Parser und Manifestzulassung

- [ ] Tests zuerst schreiben: UTF-8-JSON-Objekt zulässig; doppelte Keys, NaN/Infinity, ungültiges UTF-8, Array statt Objekt, übergroße Bytes ablehnen. Unterschiedliche Zeichen-/Bytelänge explizit prüfen.
- [ ] Fehlenden Import als anfänglichen Fehlschlag belegen; anschließend Funktionen implementieren.
- [ ] `parse_object`: vor Dekodieren Bytegrenze prüfen; `json.loads` mit eigenem `object_pairs_hook` gegen doppelte Keys und `parse_constant` gegen Sonderzahlen; nur dict zurückgeben. Fehler stets `ContractError('invalid_request')`, Größenüberschreitung `payload_limit`. Keine Rohdaten in Fehlertexten.
- [ ] `validate_manifest`: exakte synthetische Schlüsselmenge `{profile_revision, abi_surface, abi_version, kernel_id, release_id, schema_id, operations, entry}`. Freigegebene Werte aus separatem `approved`, niemals aus demselben Manifest ableiten. `operations` exakt `['analysis']`; Oberfläche rest, ABI v1. Alle skalaren Felder echte Strings. `entry` muss String sein, wird ausschließlich als ignorierte Kompatibilitätsmetadaten behandelt; niemals importieren oder ausführen.
- [ ] Unbekannte Revision, falsche Typen, fehlende/zusätzliche Felder, geänderte Release-/Schema-ID und Operationsliste separat testen. Dies ist Identitätsvergleich im Testmodell, kein tatsächlicher Dateihash-/Deploymentbeleg.

Konkrete Testform:

```python
def test_duplicate_key_is_rejected(self):
    with self.assertRaises(ContractError) as caught:
        parse_object(b'{"tenant_id":"A","tenant_id":"B"}', 1024)
    self.assertEqual(caught.exception.code, 'invalid_request')
```

## 2. Kontext und aktuelle Testberechtigung

- [ ] Fixture enthält exakt context_version, request_id, tenant_id, actor_id, audience, operation, issued_at, expires_at, authorization_revision, profile_revision, release_id.
- [ ] IDs nichtleer, ASCII-Muster `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`; keine stillen Defaultwerte. Profilrevision separat exakt vergleichen. Zeitwerte `type(value) is int`, damit bool nicht als Zeit akzeptiert wird.
- [ ] Ablaufregel: `issued_at <= now < expires_at` und `0 < expires_at-issued_at <= 30`. Ziel/Operation/Profil/Release gegen vertrauenswürdiges approved prüfen. Kontextrevision im Labor `synthetic-context-v1`, keine Behauptung eines finalen Wireformats.
- [ ] TestAuthority hält Tupel `(tenant, actor, audience, operation, revision)`. Leere/unbekannte Kombination verweigern; Revoke entfernt nur exaktes Tupel. Kein globaler Default, keine Vererbung zwischen A/B. Fake-Authority explizit benennen, nicht als echte Sitzungsauswertung darstellen.
- [ ] authorize_analysis prüft jeden Aufruf neu. Fälle: gültig; fehlender/fremder Akteur oder Mandant; falsches Ziel; alte Rechteversion; Entzug zwischen zwei Prüfungen; Ablauf exakt auf Grenze; Zukunft; überlange Gültigkeit; bool als Zeit.

Konkrete Testform mit frischen Fixtures je Test:

```python
def test_expiry_boundary(self):
    context = self.context(issued_at=100, expires_at=130)
    validate_context(context, self.approved, 129)
    with self.assertRaises(ContractError):
        validate_context(context, self.approved, 130)
```

Kein Test behauptet Transportauthentifizierung, Datenbank-/Cacheisolation oder Rechteentzug während einer echten CPU-Ausführung.

## 3. Slot-Zustandsmodell

- [ ] Startzustand idle. reserve nur idle → reserved; start nur reserved → running. Zweite Reservierung in jedem belegten Zustand sperren, ohne bestehende ID zu ändern.
- [ ] request_abort nur running → abort_requested. finish ausschließlich running/abort_requested mit einer der Ausgänge succeeded, failed, aborted; outcome als Ergebnis speichern und Slot idle setzen. Nach abort_requested kein succeeded im engen Testmodell. Andere Übergänge geben festen state_conflict zurück, Zustand bleibt unverändert.
- [ ] lose_observation setzt jeden belegten Zustand auf unknown. unknown erlaubt keine reserve/start/finish; eine tatsächliche Recoveryfunktion ist ausdrücklich nicht Teil von T1.
- [ ] Tests überprüfen Zustände vor/nach jedem gültigen und ungültigen Übergang. Keine Hintergrundarbeit oder Retryfunktion; zweimalige Autorisierung erzeugt keine Ausführung.

```python
def test_unknown_slot_stays_blocked(self):
    slot = TrialSlot()
    slot.reserve('request-1')
    slot.start()
    slot.lose_observation()
    with self.assertRaises(ContractError):
        slot.reserve('request-2')
    self.assertEqual(slot.state, 'unknown')
```

finish im Testmodell bekommt einen behaupteten Abschluss vom Test. T3 muss erst beweisen, woher ein vertrauenswürdiger Prozessabschluss kommt; T1 liefert dafür keinen Nachweis.
