# T3 – Ubuntu-Prozess- und Recovery-Vorbereitung

> Umsetzung inline mit superpowers:executing-plans, keine automatische Delegation. Dies ist die konkrete Testabgrenzung; ausführbarer Code wird erst mit gezielten RED/GREEN-Tests ergänzt.

**Ziel:** B07–B09 am isolierten synthetischen Testpaket nachweisen, ohne Produktcode oder Serverboot anzufassen.

**Architektur:** Eigene kurzlebige systemd-Systemdienste mit DynamicUser, eindeutiger Laufkennung und cgroup-v2-Limits. Ein separates begrenztes SQLite-Testjournal gehört dem Controller; der Worker erhält keinen Schreibzugriff darauf. Kein Anschluss an das Governor-Journal, keine Produktzertifikate, keine Fach- oder Backupdaten.

**Technik:** Python-Standardbibliothek, SQLite, vorhandenes systemd/OpenSSL; keine zusätzliche Installation. Bestehende T1/T2-Dateien bleiben unabhängig. Lokale Entwicklung im genehmigten Brainpower-Bereich; kein Worktree des übergeordneten Benutzerprofil-Repositories.

## Festgelegter enger Testumfang

| Gegenstand | Festlegung für synthetische Tests |
|---|---|
| Ablage | Separater root-eigener Bereich `/var/tmp/aurelia-t3/<run-id>`; zufällige 128-Bit-ID, keine Symlinks, Abbruch bei vorhandener Zielinstanz |
| Dienstname | `aurelia-t3-<run-id>.service`; nie Wildcard-stop/kill oder Zugriff auf fremde Einheiten |
| Identität | Lauf-ID + systemd InvocationID + ControlGroup + Boot-ID; PID allein unzureichend |
| Rechte | DynamicUser, NoNewPrivileges, ProtectSystem=strict, ProtectHome, PrivateTmp; Paket root-eigen und nur lesbar; keine Secrets im Paket |
| Netzwerk | Zuerst Prozessprüfungen ohne Netzwerk (PrivateNetwork); spätere Linux-TLS-Prüfungen gesondert, ausschließlich Loopback |
| Limits | MemoryMax=128M, MemorySwapMax=0, TasksMax=16, CPUQuota=25%, RuntimeMaxSec=20s, TimeoutStopSec=2s, KillMode=control-group, SendSIGKILL=yes, Restart=no |
| CPU-Nachweis | CPUQuota ist Bandbreite, kein gesamtes CPU-Zeitbudget. Effektive cgroup-Werte und Drosselzähler prüfen; keine harte Echtzeitgarantie behaupten |
| Abbruch | Worker ignoriert SIGTERM und erzeugt eigenen Kindprozess; Ende aller eigenen Prozesse/cgroup nach SIGKILL beobachten. Beobachtungsfrist 5 s nach Stop-Aufruf; Überschreitung ist Fehler, keine nachträgliche Toleranzänderung |
| Journal | SQLite FULL-Synchronisierung; Reservierung vor Start committen; ein aktiver Slot, kein Replay. Pro Lauf höchstens 100 Ereignisse / 1 MiB Metadaten, keine Payloads/Schlüssel. Fehler beim Schreiben sperrt neue Arbeit |
| Wiederanlauf | Offener Beleg wird ungeklärt. Kein automatischer Neustart des Workers. Fehlendes Ende hält Sperre; belegtes Ende erlaubt gesonderte technische Freigabe, fachlicher Ausgang bleibt unbekannt |
| Aufbewahrung | Temporäre Schlüssel nach Test entfernen; bereinigter Bericht und Hashmanifest lokal behalten. Serverdateien nur bei geprüfter Eigentums-/Pfadbindung gezielt entfernen; unklare Identität führt zu Halt |

Diese Limits sind Testwerte für kleine synthetische Worker, keine Produktionsdimensionierung. DynamicUser/systemd-Härtung ist keine zugesagte Sandbox für feindlichen nativen Code. Root-Controller führt nur feste eigene Befehle mit Argumentlisten aus; niemals Modelleingaben oder HTTP-Daten als Shellcode.
